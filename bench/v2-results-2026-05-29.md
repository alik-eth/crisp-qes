# CRISP-QES **v2** prover & verifier benchmarks — 2026-05-29

Git commit: `f2ab5b4` (contracts: v2 — EnrollmentRegistry + PetitionRegistryV2)

Methodology mirrors [`bench/results-2026-05-28.md`](results-2026-05-28.md)
1:1 so the comparison to MVP is apples-to-apples. Same hardware, same
bb.js / noir_js versions, same Playwright + Chromium build, same
`verifierTarget:"evm"` setting.

## Circuit shape

| Field                  | MVP                                          | v2                                              | Δ                |
| ---------------------- | -------------------------------------------- | ----------------------------------------------- | ---------------- |
| ACIR JSON size         | 1,137,336 B                                  | **88,983 B**                                    | **0.078× (13× smaller)** |
| UltraHonk gates        | ~100 k (estimate)                            | **28,688**                                      | ~0.29×           |
| ACIR opcodes           | n/a                                          | 1,385                                           | —                |
| User-visible publics   | 15 (CAdES + ECDSA + binding)                 | **3** (`petition_id`, `enrollment_root`, `nullifier`) | 0.20×       |
| Bundled publics (vk)   | 31                                           | 19                                              | 0.61×            |
| Private witness        | full signedAttrs + leaf/inter certs + path   | `enrollment_secret` + `merkle_path[20]` + indices |             |
| In-circuit ops         | 2× P-256 ECDSA verify, SHA-256, Merkle       | 1× Merkle (depth 20) + 1× Pedersen for nullifier |             |
| Solidity verifier      |                                              |                                                 |                  |
| - source .sol size     | 23 k LoC                                     | 100,107 B (source) / **23,726 B (deployed)**    | ≈ MVP            |
| - EIP-170 headroom     | +855 B                                       | **+850 B** (safe)                               | identical        |

The v2 design pushes both ECDSA verifications **off** the ZK circuit —
they're absorbed into the off-chain enrollment step (OPRF + Diia QES
check at enrollment time, not per-signature). The in-circuit work
collapses to just `compute_root` (20× Pedersen) and `pedersen_hash` for
the nullifier.

## 1. Native prover (Node + bb.js WASM)

Harness: [`bench/v2-native-prove.mjs`](v2-native-prove.mjs). Same
methodology as MVP: fresh `Barretenberg` per run, `Noir.execute()` →
`UltraHonkBackend.generateProof({verifierTarget:"evm"})`, peak RSS
sampled every 100 ms.

| Variant                  | n | witness (ms) median | prove (ms) median | prove mean ± σ | proof bytes | peak RSS  |
| ------------------------ | - | ------------------- | ----------------- | -------------- | ----------- | --------- |
| `threads=auto` (16 vCPU) | 5 | 24                  | **474**           | **475 ± 11**   | 8,640       | 228 MB    |
| `threads=1`              | 5 | 25                  | 1,350             | 1,352 ± 33     | 8,640       | 225 MB    |

threads=1 is only **~2.85× slower** than threads=auto — bb.js extracts
limited parallelism from a 1.3 k-opcode circuit. Both variants converge
in steady state (run-1 is slightly slower due to wasm warmup); σ is
~2 % of mean, very tight.

### vs MVP

| Metric              | MVP (n=5, threaded) | v2 (n=5, threaded) | ratio  |
| ------------------- | ------------------- | ------------------ | ------ |
| witness median (ms) | 1,268               | **24**             | 0.019× (**53× faster**) |
| prove median (ms)   | 14,458              | **474**            | 0.033× (**30× faster**) |
| peak RSS (MB)       | 346                 | **228**            | 0.66× (34 % smaller)    |
| proof size (B)      | 10,176              | **8,640**          | 0.85× (15 % smaller)    |

Raw per-run records:
[`v2-native-multi-*.json`](v2-native-multi-2026-05-28T21-53-41-190Z.json),
[`v2-native-single-*.json`](v2-native-single-2026-05-28T21-56-13-589Z.json).

## 2. Browser / WASM prover (Playwright)

Harness: [`bench/v2-web-prove.mjs`](v2-web-prove.mjs). Drives the
**MVP** live web app (https://crisp-qes-web.fly.dev) because the v2
web app from #33 hasn't deployed yet. Same bb.js, same COOP/COEP, same
worker bundle — only the circuit JSON served at
`/crisp_qes_circuit.json` is route-intercepted to return the v2 ACIR
JSON, and the witness POSTed to the worker matches the v2 shape. This
gives a real-browser real-wasm timing without waiting on v2 web deploy.

| Run        | total (ms) | prove (ms) | proof bytes |
| ---------- | ---------- | ---------- | ----------- |
| 1 (cold)   | 3,592      | 3,514      | 8,640       |
| 2          | 2,436      | 2,357      | 8,640       |
| 3          | 2,392      | 2,311      | 8,640       |
| **mean**   | 2,807      | **2,727**  | 8,640       |
| **median** | 2,436      | **2,357**  | 8,640       |

The bb.js wasm needs a one-shot warmup on first prove (run 1 is ~1.2 s
slower than runs 2/3); steady state is ~2.3 s.

### vs MVP

| Metric            | MVP (n=3) | v2 (n=3)  | ratio                          |
| ----------------- | --------- | --------- | ------------------------------ |
| prove median (ms) | 79,729    | **2,357** | 0.030× (**34× faster**)        |
| prove mean (ms)   | 76,962    | **2,727** | 0.035× (**28× faster**)        |
| proof size (B)    | 10,176    | **8,640** | 0.85×                          |

**Headline target was < 10 s — landed at 2.4 s, 4× under target.**

## 3. On-chain verifier gas

Measured via `forge test --gas-report` against the actual deployed-
bytecode UltraVerifierV2 + a real proof emitted by `bench/v2-emit-proof.mjs`.
Two tests:

1. **`test_verify_gas`** — UltraVerifierV2.verify() in isolation
   (proof + publicInputs in, bool out). Comparable to the MVP
   `UltraVerifier::verify` subtree we extracted from
   `cast run 0x349d…65c47` (2,676,476 gas).
2. **`test_signPetition_e2e_gas`** — full PetitionRegistryV2.signPetition
   call with the real verifier wired in. Comparable to the MVP's
   on-chain tx total of 4,242,422 gas.

| Component                                            | MVP gas    | v2 gas        | ratio                |
| ---------------------------------------------------- | ---------- | ------------- | -------------------- |
| `UltraVerifier(V2).verify` (isolated)                | 2,676,476  | **2,417,572** | 0.90× (10 % cheaper) |
| Full `signPetition` (e2e, real verifier)             | 4,242,422  | **2,620,543** | **0.62× (38 % cheaper)** |
| Verifier `deployedBytecode` (EIP-170 / 24,576 B cap) | 23,721 B   | 23,726 B      | 1.00×                |
| Verifier `Deployment Cost`                           | n/a        | 5,181,625     | —                    |
| `EnrollmentRegistry` deploymentCost (one-time)       | (none)     | 381,439       | —                    |
| `PetitionRegistryV2` deploymentCost (one-time)       | n/a        | 1,344,126     | —                    |
| `createPetition` (one-time per petition)             | n/a (MVP similar) | 121,380 | —                    |

### Cost per signature in fiat

Assuming the same Base Sepolia effectiveGasPrice as the MVP demo tx
(6,000,000 wei = 0.006 gwei) and the same L1-fee shape:

```
v2 signPetition ≈ 2,620,543 gas × 6e6 wei = 1.572 × 10⁻⁵ ETH on L2
                + ~5 × 10⁻⁷ ETH L1 blob (similar to MVP)
                ≈ 1.62 × 10⁻⁵ ETH total
```

| ETH price | MVP cost / sig | v2 cost / sig | savings |
| --------- | -------------- | ------------- | ------- |
| $3,500    | $0.091         | **$0.057**    | 37 %    |
| $2,500    | $0.065         | **$0.041**    | 37 %    |

**Headline target was < 2 M gas — landed at 2.62 M, honest miss but a
clean 38 % reduction from MVP.** The remaining cost is dominated by the
Honk verifier itself (~92 % of total); further compression would need a
different proving system (Plonk, Groth16) rather than circuit-level
optimization.

Test harness: [`packages/v2-contracts/test/UltraVerifierV2Gas.t.sol`](../packages/v2-contracts/test/UltraVerifierV2Gas.t.sol).
Proof artifact: [`bench/v2-proof.bin`](v2-proof.bin) (8,640 B).

## 4. Mobile feasibility (CPU-throttled Chromium)

Same CDP `Emulation.setCPUThrottlingRate` caveat as MVP: throttling
slows V8 main thread but **does not propagate to dedicated Web Workers**
in Chromium 149. v2 prove runs in a worker → throttled numbers will be
unchanged from baseline.

| Variant            | n | prove (ms) median | notes                                  |
| ------------------ | - | ----------------- | -------------------------------------- |
| Chromium baseline  | 3 | **2,357**         | from § 2 above                         |
| Chromium @ 4× CPU  | 2 | 3,161             | worker untouched, see caveat           |

Honest mobile estimate via Geekbench-extrapolation (single-core ratio
of mobile chip vs this 2.6 GHz Xeon core):

| Target class            | GB6 SC ratio vs box | est. v2 prove time |
| ----------------------- | ------------------- | ------------------ |
| iPhone 15 Pro (A17 Pro) | ~1.0×               | **~2.4 s**         |
| Pixel 8 (Tensor G3)     | ~1.8×               | **~4.2 s**         |
| Galaxy A54 (Exynos 1380)| ~3.0×               | **~7.1 s**         |
| Low-end 2020 Android    | ~5.0×               | **~12 s**          |

**Every device class except the bottom-tier 2020 Android lands under
10 s.** The landing copy's "30 s – 2 min" promise from MVP can be
revised to "2 s – 12 s" for v2.

Memory: native peak RSS 228 MB, worker-side wasm allocation likely
<256 MiB (stays comfortably under per-tab limits on every modern
mobile browser).

Raw: [`v2-web-chromium-cpuThrottle4-*.json`](v2-web-chromium-cpuThrottle4-2026-05-28T21-57-28-992Z.json).

## 5. Headline numbers (for grant + README)

- **v2 proof generation, desktop browser (n=3):** **median 2.4 s** (down from MVP 79.7 s — **34× faster**)
- **v2 proof generation, native Node (n=5, threads=auto):** **median 474 ms** (down from MVP 14.5 s — **30× faster**)
- **v2 on-chain signature cost, Base Sepolia (forge gas-report):** **2,620,543 gas → ≈ $0.057 per signature** at ETH = $3,500 (down from MVP $0.091 — **38 % cheaper**)
- **v2 proof size on the wire:** **8,640 bytes** (down from MVP 10,176 B — 15 % smaller)

### Targets vs reality

| Target           | Pitched | Measured  | Status     |
| ---------------- | ------- | --------- | ---------- |
| Browser prove    | < 10 s  | **2.4 s** | ✅ 4× under |
| On-chain gas     | < 2 M   | 2.62 M    | ❌ +31 % over |

The verifier-gas miss is honest: the Honk EVM verifier is the floor,
and we already pay <10 % of MVP's `UltraVerifier.verify`. Further
on-chain savings would require swapping proving system.

## Reproducing

```sh
# Pre-generate one proof for the forge gas test:
node bench/v2-emit-proof.mjs            # writes bench/v2-proof.bin

# Native
node bench/v2-native-prove.mjs --threads=auto --runs=5 --label=multi
node bench/v2-native-prove.mjs --threads=1     --runs=5 --label=single

# Browser (route-intercepts the MVP host's circuit URL until v2 web ships)
node bench/v2-web-prove.mjs    --runs=3        --browser=chromium
node bench/v2-web-prove.mjs    --runs=2        --browser=chromium --cpuThrottle=4

# On-chain verifier + e2e signPetition gas
( cd packages/v2-contracts && forge test --match-contract UltraVerifierV2GasTest --gas-report )
```
