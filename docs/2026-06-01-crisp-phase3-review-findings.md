## [1] CRITICAL — petition_id is caller-chosen and unbound to the round, enabling unlimited double-voting in a single tally

- **Dimension:** contract · **claimed:** critical · **verifier confidence:** high
- **File:** `packages/crisp-contracts/contracts/CRISPQESProgram.sol`
- **Location:** publishInput, lines 174-193 (abi.decode of petitionId) and pub[6] = bytes32(petitionId); _processVote dedup is keyed on nullifier (lines 269-293)

**Issue:** The whole one-person-one-vote guarantee rests on the nullifier being a deterministic function of the enrollment secret for THIS petition: per the leaf circuit (circuits/bin/crisp_qes/src/main.nr:191,246-247) the real-vote branch asserts `nullifier == pedersen_hash([enrollment_secret, petition_id, DOMAIN_PETITION_V2])` and membership of `enrollment_secret`. petition_id is public input pub[6]. In the contract, `petitionId` is taken verbatim from `abi.decode(data, ...)` (line 177) and forwarded straight to `pub[6] = bytes32(petitionId)` (line 193). Nothing pins petition_id to the e3Id/round: only `enrollmentRoot` (per-e3Id, set once) and `numOptions` are stored and checked; there is no `require(petitionId == <value bound to e3Id>)`. Dedup in `_processVote` is keyed solely on the resulting `nullifier` within `e3Data[e3Id].voteSlots`. Because the nullifier is a function of petition_id, a single legitimately-enrolled secret `s` can mint arbitrarily many DISTINCT nullifiers for the SAME round by varying petition_id: pick p1 -> N1 = pedersen([s,p1,DOM]), p2 -> N2, ... Each real-vote proof is independently valid (membership of s holds; nullifier matches its own pub[6]=p_i; valid one-hot ballot), and each Ni is a fresh, un-voted slot in the same e3Id tally. SlotAlreadyVoted never triggers because the keys differ.

**Impact:** Critical vote-integrity / double-vote break. One enrolled person can cast unbounded real votes in a single petition's tally (vote-stuffing / ballot-box stuffing), defeating one-person-one-vote and Sybil resistance — the core property of the QES enrollment model. The on-chain Honk verifier accepts every such proof; the FHE tally counts every slot. Exploitable by any single eligible voter with no extra credentials.

**Recommendation:** Bind petition_id to the round on-chain. Simplest: store the round's petition_id at initialization (carry it in customParams/e3ProgramParams in `validate`, e.g. e3Data[e3Id].petitionId), then in publishInput drop the calldata petitionId entirely and set `pub[6] = bytes32(e3Data[e3Id].petitionId)`. Reject votes for any other petition_id by construction. (Note the mask path legitimately uses petition_id=0, so if masks must keep pub[6]=0, gate the binding on `!isMask` — but verify the mask path cannot then be abused to mint extra REAL slots, since masks require an already-existing slot.)

**Verifier:** Confirmed by reading the code. In the circuit (circuits/bin/crisp_qes/src/main.nr): petition_id is a public input (line 160 `petition_id: pub Field`), and the real-vote branch asserts `nullifier == pedersen_hash([enrollment_secret, petition_id, DOMAIN_PETITION_V2])` (lines 191, 247) plus Merkle membership of enrollment_secret (lines 244-246). So the nullifier is a deterministic function of (secret, petition_id).

In the contract (CRISPQESProgram.sol): publishInput is `external` with NO access control (line 150) — any caller can submit. petitionId is taken verbatim from caller-supplied calldata via abi.decode (line 177) and forwarded straight to pub[6] = bytes32(petitionId) (line 193) before honkVerifier.verify (line 197). Nothing pins petitionId to the round: the RoundData struct (lines 28-35) stores only enrollmentRoot, paramsHash, voteSlots, votes, numOptions, creditMode — there is NO petitionId field and NO `require(petitionId == <round-bound value>)` anywhere in validate() or publishInput(). Dedup in _processVote (lines 275-284) is keyed solely on the resulting nullifier within e3Data[e3Id].voteSlots.

Therefore one genuinely-enrolled voter holding secret s and its merkle path can pick arbitrary p1,p2,... to mint distinct nullifiers N_i = pedersen([s,p_i,DOM]) for the SAME e3Id. Each proof independently satisfies membership (s is in the census), the nullifier assertion (matches its own pub[6]=p_i), and valid_vote (one-hot ballot, balance hard-set to 1). SlotAlreadyVoted (line 281) never fires because each N_i differs, so each is appended as a fresh real-vote slot and counted by the FHE tally. The RISC0 tally verify() journal binds only ciphertextOutputHash, paramsHash, inputRoot (lines 256-262) — no petition_id constraint — and no RISC0 guest references petition_id, so nothing downstream rejects the duplicates. The SDK comment in types.ts (line 170) even states the intended invariant ("petitionId binds the nullifier to this round") that the contract fails to enforce.

This defeats one-person-one-vote / Sybil resistance via vote-stuffing. Caveat: the attacker must be a legitimately enrolled census member (membership of s is asserted in-circuit), so it is not anonymous outsider Sybil — but unbounded ballot-box stuffing by any single eligible voter is itself a complete break of the core integrity property, justifying critical.

## [2] HIGH — Circuit branch selector `is_mask_vote` is a private witness, decoupled from the contract's `isMask` — lets a credentialed voter REPLACE an already-cast vote (append-only / immutability break)

- **Dimension:** circuit-soundness · **claimed:** critical · **verifier confidence:** high
- **File:** `vendor/crisp-qes-enclave/examples/CRISP/circuits/bin/crisp_qes/src/main.nr`
- **Location:** main(), `is_mask_vote: bool` param (line 165, NOT marked `pub`) + branch at lines 242-262; fold ABI in vendor/.../circuits/bin/fold/src/main.nr lines 33-42 (no is_mask in the 8 pub inputs); contract _processVote in packages/crisp-contracts/contracts/CRISPQESProgram.sol lines 269-293

**Issue:** The leaf circuit selects between the real-vote branch and the mask branch on the PRIVATE witness `is_mask_vote`. This flag is not a public input of the leaf and is not threaded through `fold` (the on-chain fold verifier has only 8 user public inputs: prev_ct_commitment, enrollment_root, nullifier, is_first_vote, num_options, final_ct_commitment, petition_id, pk_commitment — no is_mask). The contract has its OWN `isMask` bool (decoded from calldata, CRISPQESProgram.sol line 178) that drives `_processVote`, but nothing binds the contract's `isMask` to the circuit's branch. They are fully independent values the attacker controls separately. Exploit: an attacker who has already cast a real vote at nullifier N (slot exists, real path is append-only and would revert with SlotAlreadyVoted) instead submits to the contract with `isMask=true`. `_processVote` takes the MASK path: it does NOT verify ciphertext addition on-chain — it simply OVERWRITES the slot via `votes._update(uint256(commitment), voteIndex)` with the new `encryptedVoteCommitment` (= pub[5] final_ct_commitment). Meanwhile the attacker generates the proof with the circuit's `is_mask_vote=FALSE`, so the leaf runs the REAL branch (lines 242-250): it asserts membership, nullifier==pedersen([s,petition_id,DOMAIN]), and valid_vote — and crucially does NOT assert valid_zero_vote, valid_prev_ct, or valid_ct_add. `valid_vote` accepts a NONZERO ballot, and the returned final_ct_commitment is a fresh standalone ciphertext (not prev+new). The proof verifies (all real-branch asserts pass for the slot owner), and the contract overwrites the existing slot with the brand-new ballot.

**Impact:** Vote-integrity / append-only break. A voter can change/replace their already-submitted vote (e.g., flip YES->NO after observing partial signals, or re-vote with a different ballot) despite the real-vote path being declared append-only (SlotAlreadyVoted). The mask invariant 'mask votes are zero votes added to the slot' is bypassed: the slot is overwritten with an arbitrary non-zero ballot, not homomorphically summed, so the previous ciphertext is discarded entirely and the final tally reflects only the replacement ballot for that slot. This defeats the core one-immutable-ballot-per-nullifier guarantee.

**Recommendation:** Bind the branch selector to the contract. Make `is_mask_vote` (or equivalently the contract's `isMask`) a PUBLIC input of the leaf AND of fold, and have the contract feed its `isMask` into that public-input position so the verifier rejects any proof whose internal branch disagrees with the on-chain action. Equivalently, derive the branch inside the circuit from a public is_mask input rather than a free witness. Additionally, the mask/_update path overwriting a slot with a non-added commitment is dangerous on its own: the on-chain _update should only be reachable when the circuit has proven valid_ct_add (sum = prev + new); binding is_mask publicly achieves this since the mask branch enforces valid_prev_ct + valid_ct_add.

**Verifier:** Confirmed by reading the cited code. The leaf circuit's branch selector `is_mask_vote` (crisp_qes/src/main.nr:165) is a PRIVATE witness — not `pub`, not among the leaf's public inputs, and not threaded through fold (fold/src/main.nr:33-41 expose only the 8-vector prev_ct_commitment, enrollment_root, nullifier, is_first_vote, num_options, final_ct_commitment, petition_id, pk_commitment — no is_mask). The contract has its OWN independent `isMask` decoded from calldata (CRISPQESProgram.sol:178) that alone drives `_processVote`, and nothing binds the two. I verified the full exploit chain:

1. _processVote mask path (lines 286-291): on an existing slot it sets prevCommitment = old slot value, is NOT append-only, and OVERWRITES the slot via votes._update(commitment, voteIndex) with the new encryptedVoteCommitment. No on-chain ciphertext-addition check.
2. The contract derives is_first_vote (pub[3]) from prevCommitment==0, and sets pub[0]=prevCommitment, pub[5]=encryptedVoteCommitment — none of these come from / bind the proof's branch.
3. The circuit real branch (is_mask_vote=false, lines 242-250) asserts ONLY: membership root, nullifier==pedersen([s,petition_id,DOMAIN]), and valid_vote (accepts a NONZERO ballot). It does NOT assert valid_zero_vote, valid_prev_ct, valid_ct_add, and ignores both is_first_vote and prev_ct_commitment public inputs. It returns final_ct_commitment = fresh ct_commitment.

So an enrolled voter who already cast a real vote at nullifier N (holds the secret) can resubmit with contract isMask=true while proving with circuit is_mask_vote=false. All real-branch asserts pass (they are the slot owner), pub[5] matches the returned fresh ct_commitment, is_first_vote=0 and prev_ct_commitment are unconstrained in the real branch — so the proof verifies and the contract overwrites the previously-cast ballot with a brand-new arbitrary non-zero ciphertext. This bypasses the append-only SlotAlreadyVoted guard and the 'mask = zero vote homomorphically summed' invariant: the previous ciphertext is discarded, breaking one-immutable-ballot-per-nullifier and enabling vote replacement (flip YES->NO after observing signals).

Severity downgraded from critical to high for two scoping reasons (not a refutation): (a) the attack is bounded to the attacker's OWN slot — it lets a credentialed voter replace their own ballot, not forge votes for others or stuff arbitrary nullifiers; (b) the affected code is the vendored CRISP/Enclave FHE-tally variant (vendor/crisp-qes-enclave/examples/CRISP) — the live-deployed petition path is packages/contracts/src/PetitionRegistryV2.sol, which uses a simple boolean _signed mapping with no mask/_processVote branch and is immune. The defect is nonetheless a genuine, exploitable circuit-soundness/vote-integrity break in the system the finding targets.

## [3] HIGH — Malicious first broadcast can poison the locally-served enrollment root (mask-daemon DoS / receipt-freeness break)

- **Dimension:** rust-server · **claimed:** high · **verifier confidence:** high
- **File:** `server/src/server/routes/qes.rs`
- **Location:** broadcast_qes_vote, lines 128-140 (set_enrollment_root) + repo.rs set_enrollment_root lines 194-205

**Issue:** The /qes/broadcast handler takes a fully client-supplied `enrollment_root` (QesVoteRequest.enrollment_root, models.rs:149) and persists it via QesRepository::set_enrollment_root BEFORE the on-chain publishInput call (qes.rs:129-140 runs before the contract call at qes.rs:157). The repo write is an UNCONDITIONAL overwrite (repo.rs:199 `state.enrollment_root = Some(root.clone())`), with no validation against the authoritative on-chain value and no roll-back if the tx later reverts. The on-chain enrollment root is set once by the contract owner via setEnrollmentRoot (onlyOwner, CRISPQESProgram.sol:94-99) and is what the proof is actually verified against (pub[1] = e3Data[e3Id].enrollmentRoot, CRISPQESProgram.sol:188), so a poisoned local root does NOT let an attacker forge a vote. BUT the locally-stored root is exactly what /qes/enrollment-root serves to the mask-daemon (sources.ts:130-141), which feeds it as the `enrollmentRoot` public input when building mask proofs (daemon.ts:107-127, maskInput.ts). Because the contract recomputes pub[1] from its own on-chain root for both real and mask proofs, a mask proof built with the wrong root fails honkVerifier.verify on-chain and never publishes. An attacker can therefore POST a single broadcast (even one whose proof reverts, since seeding happens first and is not rolled back) carrying a bogus enrollment_root, after which the mask-daemon's sweeps all fail and no mask votes can be cast.

**Impact:** Denial of the masking mechanism, which is the platform's receipt-freeness guarantee. With masking disabled, real votes are never overwritten, so each real ciphertext stays linkable to its single original encryption (a usable voting receipt) — a privacy/coercion-resistance break. Trivially triggerable by any unauthenticated client; persists in sled until manually corrected.

**Recommendation:** Do not trust the client-supplied root. Either (a) drop enrollment_root from the broadcast API and have the coordinator seed the local root from the same source it uses to call setEnrollmentRoot on-chain (the owner already knows it), or (b) make set_enrollment_root write-once (reject if already set AND non-equal) and only seed AFTER the on-chain tx succeeds, and validate the supplied root by reading the value the owner set on-chain. At minimum, move the seeding to after a successful publish_input and reject mismatched re-seeds.

**Verifier:** Confirmed by reading the code. /qes/broadcast accepts a fully client-supplied, unvalidated enrollment_root (models.rs:149) and persists it via set_enrollment_root BEFORE the on-chain publish_input: the seed runs at qes.rs:129-140, the contract call at qes.rs:157. The repo write is an unconditional overwrite with no comparison to any authoritative value (repo.rs:198-199: state.enrollment_root = Some(root.clone())), and the broadcast handler's error path (qes.rs:218-231) does NOT roll back the seed, so an attacker's bogus root persists even when their own proof tx reverts. The route is unauthenticated — only rounds.rs gates on cron_api_key; /qes has just a CORS+logger wrap (mod.rs:68-71). The poisoned value is served verbatim by /qes/enrollment-root (qes.rs:271-292), fetched by the mask-daemon (sources.ts:129-142, BigInt-parsed with no validation), and used as the mask proof's pub[1] (maskInput.ts:66; daemon.ts:107/127). The contract always sets pub[1] = its own set-once on-chain enrollmentRoot for every publishInput (CRISPQESProgram.sol:188, owner-set sol:94-99) and verifies it (sol:197), so a wrong root makes every mask proof fail honkVerifier.verify — exactly the SumcheckFailed condition the code comments at maskInput.ts:38-43 warn about. The finding correctly scopes the impact: NOT a vote-forgery/integrity break (the on-chain root is authoritative), but a sustainable, unauthenticated DoS of the masking mechanism that provides receipt-freeness/coercion-resistance. The attacker can re-poison after any honest broadcast re-seeds the correct value. Net: real, trivially triggerable, persists in sled. Severity stays high — it disables a core stated privacy guarantee — though the privacy harm is conditional on an external coercer correlating the now-unmasked ciphertext and is operator-recoverable, so it is not critical (no integrity/forgery and no direct standalone deanonymization).

## [4] HIGH — is_mask_vote is a private witness, never bound to the on-chain isMask routing flag — anyone can insert a credential-free "real" vote slot (Sybil/append-only invariant break + tally-tree DoS)

- **Dimension:** protocol-security · **claimed:** high · **verifier confidence:** high
- **File:** `vendor/crisp-qes-enclave/examples/CRISP/circuits/bin/crisp_qes/src/main.nr (mask path), examples/CRISP/circuits/bin/fold/src/main.nr (fold public inputs), examples/CRISP/packages/crisp-contracts/contracts/CRISPQESProgram.sol:174-202, 269-293`
- **Location:** main.nr fn main param is_mask_vote (line 165, NOT pub); fold/main.nr (is_mask_vote absent from the 7 pub inputs); CRISPQESProgram.publishInput decodes isMask from calldata (line 181) and routes _processVote on it (line 279)

**Issue:** The leaf's branch selector `is_mask_vote` is a PRIVATE input (main.nr:165) and is not among the fold circuit's public inputs (fold/main.nr:33-41 expose only prev_ct_commitment, enrollment_root, nullifier, is_first_vote, num_options, final_ct_commitment, petition_id, pk_commitment). The on-chain proof is the fold proof, so nothing in the verified public-input vector tells the contract whether the proof was produced on the credential-bearing real-vote path or the credential-free mask path. The contract instead reads `isMask` from attacker-controlled calldata (abi.decode at line 181) and uses it alone to pick the _processVote branch. Because the mask path asserts NO membership and leaves `nullifier`, `enrollment_root`, and `petition_id` as free, attacker-chosen witnesses (confirmed by buildMaskProofInputs in services/mask-daemon/src/maskInput.ts, which sets enrollmentSecret=0 and a chosen nullifier), an attacker with no enrollment credential can: (1) generate a valid mask/first-vote proof (is_mask_vote=true, is_first_vote=true, k1=0) with an arbitrary fresh nullifier and the round's public enrollment_root; (2) submit it with calldata isMask=FALSE. The contract's real-vote branch (line 279-285) sees a fresh nullifier, creates a new slot, and inserts the (zero) ciphertext into the votes LazyIMT. The honk verify passes because pub[3]=is_first_vote=1 matches the proof and the mask path imposes no credential constraint.

**Impact:** Breaks the core stated invariant that the votes tree only ever admits ballots from enrolled persons ('the nullifier is the cleartext gate that admits exactly one ballot per person into the blind homomorphic sum'). An unenrolled actor can write entries into the on-chain votes tree at will. The inserted ballots are forced to zero (mask path requires k1==0), so this does NOT flip the numeric tally, but it (a) lets a non-member spam the depth-20 votes IMT toward its 2^20-leaf capacity and inflate gas/proving cost of the RISC0 tally — a denial-of-service on the tally, and (b) destroys the auditability claim that every slot corresponds to a distinct eligible person. It does NOT yield a counted fake vote (only the real-vote path, which enforces membership, can carry a non-zero ballot), which is why this is high and not critical. The symmetric direction (real-vote proof submitted with isMask=true) is blocked by the is_first_vote/prevCommitment consistency check, and overwriting an honest slot is blocked by SlotAlreadyVoted, so the exploit is confined to spam/invariant-break.

**Recommendation:** Bind the mode to the proof. Promote `is_mask_vote` to a public input of the leaf AND the fold circuit, include it in the contract's pub[] vector, and require it to equal the calldata `isMask` (or better, derive the routing solely from a proof-bound flag and drop the calldata bool). Re-generate the fold VK and bump NUMBER_OF_PUBLIC_INPUTS accordingly.

**Verifier:** Confirmed by reading the cited code. The routing flag `isMask` is not cryptographically bound to the verified proof:

1) main.nr:165 — `is_mask_vote: bool` is a PRIVATE leaf witness (no `pub`). The leaf's public-input vector (header section C) is [prev_ct_commitment, petition_id, enrollment_root, nullifier, is_first_vote, num_options] + 3 returns; is_mask_vote is absent.

So nothing in the verified public-input vector tells the contract whether the proof took the credential-bearing real-vote path or the credential-free mask path.

3) CRISPQESProgram.sol:174-202 — publishInput abi.decodes `isMask` from attacker calldata (line 178/181) and routes _processVote on it alone (line 183). It builds pub[3]=is_first_vote from prevCommitment==0; in the real-vote branch prevCommitment is hard-set to 0 (line 282) so pub[3] is always 1. pub[1]=round enrollmentRoot, pub[2]=nullifier (calldata), pub[6]=petitionId (calldata).

## [5] MEDIUM — petition_id (pub[6]) is never validated against e3Id on-chain — round/petition binding is cosmetic

- **Dimension:** protocol-security · **claimed:** medium · **verifier confidence:** high
- **File:** `vendor/crisp-qes-enclave/examples/CRISP/packages/crisp-contracts/contracts/CRISPQESProgram.sol`
- **Location:** publishInput lines 174-194: petitionId is abi.decoded from calldata and forwarded to pub[6] with no check; RoundData has no petitionId field and e3Id is never tied to a petition_id

**Issue:** The nullifier is bound in-circuit to petition_id (nullifier = pedersen([s, petition_id, DOMAIN]) on the real-vote path), which is the mechanism the design relies on for one-ballot-per-person-per-petition and cross-petition unlinkability. But on chain, `petitionId` is a free attacker-supplied value (decoded at line 181, written to pub[6] at line 193) and is never checked to match the round (e3Id). Dedup is keyed by (e3Id, nullifier), so per-round dedup still holds, but the contract provides no guarantee that the petition_id the voter committed to corresponds to the e3 round they are voting in. The voter (or relayer) is trusted to set petition_id to the round's intended petition. If the same enrollment_root is reused across multiple e3 rounds intended to be 'the same petition,' a voter could derive different nullifiers (by choosing different petition_id values) and vote once per round without the protocol detecting it as the same petition — the per-petition-uniqueness guarantee degrades to per-round-uniqueness, enforced only by operational discipline.

**Impact:** One-person-one-vote-per-petition is not enforced end-to-end when an enrollment root is shared across rounds; it collapses to one-vote-per-(round,nullifier). Whether this is exploitable depends entirely on the deployment's round<->petition mapping, which the contract does not constrain. At minimum it is a latent integrity gap and a footgun.

**Recommendation:** Store the intended petition_id per e3Id (e.g. set alongside numOptions/enrollmentRoot in validate()/setEnrollmentRoot) and assert decoded petitionId == e3Data[e3Id].petitionId in publishInput before forwarding to pub[6]. Document the invariant that each petition gets exactly one e3 round, or bind e3Id itself into the nullifier domain.

Facts confirmed:
1. publishInput decodes petitionId from attacker-controlled calldata (line 177/181) and forwards it verbatim to pub[6] (line 193) with zero validation.
